## 📊 执行摘要

### 方法改进

之前的分析存在**跨instance对比**的问题，即在不同组别中比较完成率和解决率，但这些instance本身可能难度不同。

**本分析的改进**：
- 对同一组instance在v1、v2、v3三次测试中进行**纵向对比**
- 分析同一instance在不同版本中的表现变化
- 按fuzz工具使用模式将100个instance分为4组

### 四组分类

| 组别 | 实例数 | 定义 |
|------|--------|------|
| ✅ 稳定使用fuzz | 34 | v2和v3都使用fuzz_hypo |
| ⚠️ 仅v2使用fuzz | 11 | 仅v2使用fuzz_hypo，v3未使用 |
| ⚠️ 仅v3使用fuzz | 23 | 仅v3使用fuzz_hypo，v2未使用 |
| ❌ 从不使用fuzz | 32 | v2和v3都不使用fuzz_hypo |

### 关键发现总结

#### 1️⃣ fuzz工具对Token消耗的影响巨大

**使用fuzz工具的组**：
- 稳定使用fuzz: Token减少 **45.8%** ✅
- 仅v3使用fuzz: Token减少 **45.6%** ✅

**不使用fuzz工具的组**：
- 从不使用fuzz: Token增加 3.3% ⚠️
- 仅v2使用fuzz (v3放弃): Token增加 21.2% ⚠️

**结论**：fuzz工具是Token节省的主要驱动力！

#### 2️⃣ 工具可靠性影响agent决策

**"仅v2使用fuzz"组的故事**：
- v2时使用fuzz → Token减少53%
- v3时放弃fuzz → Token暴增158%
- 最终Token比v1还高21%

**"仅v3使用fuzz"组的故事**：
- v2时未使用fuzz → Token增加10%
- v3时开始使用fuzz → Token暴降51%
- 最终Token比v1减少46%

**结论**：v2工具失效导致11个instance放弃使用；v3工具可靠吸引23个instance开始使用。

#### 3️⃣ 稳定使用fuzz组表现最优

| 指标 | 稳定使用fuzz | 其他三组平均 | 优势 |

| v1→v3 Token变化 | **-45.8%** | -6.9% | **-38.9%** |

**结论**：稳定使用fuzz的instance在所有指标上都最优。

#### 4️⃣ 从不使用fuzz组可能是最困难的问题

| 指标 | 从不使用fuzz | 其他三组平均 |

- 或者agent没有正确识别出这些问题适合使用fuzz

#### 5️⃣ v2虽然工具失效，但仍有积极影响

所有四组在v1→v2都有改进：
- 完成数增加：7-8个instance

## 📄 数据说明

### 数据来源

- v1_no_fuzz: eval_outputs_100
- v2_buggy_fuzz: eval_outputs_hypothesis_100
- v3_fixed_fuzz: eval_outputs_hypothesis_100_fixed

### 分类方法

基于v2和v3中fuzz_hypo的调用次数：
- stable_fuzz: v2_count > 0 AND v3_count > 0
- only_v2_fuzz: v2_count > 0 AND v3_count == 0
- only_v3_fuzz: v2_count == 0 AND v3_count > 0
- never_fuzz: v2_count == 0 AND v3_count == 0

### 关键指标

- **完成率**: 完成实例数 / 总实例数
- **解决率**: 解决实例数 / 总实例数
- **Token变化**: (新版本Token - 旧版本Token) / 旧版本Token × 100%
